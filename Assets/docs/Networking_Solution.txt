================================================================================
CHOSEN NETWORKING SOLUTION: FISH-NET + DEDICATED CLOUD SERVER ARCHITECTURE
================================================================================

1. OVERVIEW & TECH STACK
--------------------------------------------------------------------------------
Game Title: Passing Over It (Bomb-Tag Multiplayer)
Target Platforms: Android (Google Play) & PC (Steam / itch.io)
Target Match Size: 10-20 Players per server instance
Server Host Target: Linux x86_64 (Ubuntu / Debian VPS) & Windows Dedicated Server
Local Test Target: Local PC Standalone Dedicated Server process + Unity Editor Client

Selected Tech Stack:
- Networking Core: Fish-Net (FishNet Networking Evolution)
- Transport Protocol: Tugboat Transport (Direct UDP Socket)
- Server Architecture: Headless / Standalone Dedicated Cloud Server
- Connection Mode: Direct IP & Port (Default: 127.0.0.1:7777 for local test, VPS Public IP for launch)


2. WHY DEDICATED CLOUD SERVER WAS CHOSEN OVER HOST-CLIENT
--------------------------------------------------------------------------------
a) 100% Server Authority & Security:
   - Crucial for bomb-tag mechanics. Bomb ownership, tag collision validation, countdown
     timers, and round eliminations are processed strictly by the dedicated server process,
     preventing host migration drops and client-side memory editing hacks.

b) Zero Host Lag / Asymmetry:
   - In Host-Client, the host player has 0ms latency while other players suffer ping lag.
     A Dedicated Server treats all 10-20 players equally, providing smooth, fair gameplay.

c) Highest Performance & Bandwidth Efficiency:
   - Tugboat (UDP socket transport) combined with Fish-Net delivers minimal CPU overhead.
   - Headless server builds run without graphics rendering (-nographics -batchmode), consuming <150MB RAM.

d) Built-in Client Prediction & Reconciliation:
   - Fish-Net's client-side prediction prevents input delay on fast movement, dashing, and diving.

e) Flexible Hosting & Scaling:
   - Free local testing on developer PC during build/iteration phase.
   - Low-cost deployment to any Linux VPS (Ubuntu/Debian) or Windows Server instance.


3. ARCHITECTURE & GAME STATE MANAGEMENT
--------------------------------------------------------------------------------
- Server Execution: Standalone executable automatically parses command-line arguments (-batchmode -nographics -port 7777 -maxplayers 20).
- Auto Scene Load: Upon server start, DedicatedServerManager automatically loads the Arena scene (Build Index 1) and listens for client UDP sockets.
- Bomb Ownership: Server-synced NetworkVariable<ulong> or ServerRPC/ObserversRPC.
- Player Sync: Fish-Net NetworkTransform with client prediction for fast movement.
- Round State Machine: Round 1, 2, 3 thresholds and elimination states handled authoritatively by Dedicated Server.


4. IMPLEMENTATION ROADMAP & WORKFLOW
--------------------------------------------------------------------------------
Step 1: Core Setup
  - Install Fish-Net via Unity Asset Store / UPM.
  - Setup Tugboat transport default port (7777 UDP).

Step 2: Server Bootstrapping & Connection Managers
  - Implement ServerCommandLineArgs.cs to parse CLI flags (-port, -maxplayers, -dedicated).
  - Implement DedicatedServerManager.cs for server startup and client IP connection handling.

Step 3: UI & In-Game Overlay
  - Implement MultiplayerMenuUI.cs with Direct IP & Port inputs + Quick Localhost (127.0.0.1:7777) preset.
  - Implement InGameNetworkHUD.cs to display server IP, port, ping, and player connection stats.

Step 4: Local PC Testing & VPS Deployment
  - Local PC Testing: Build Windows Dedicated Server or run executable with -batchmode flag. Connect from Unity Editor as Client.
  - VPS Deployment: Build Linux x86_64 server build, upload to Linux VPS, configure firewall UDP port 7777, and run as systemd background service.
